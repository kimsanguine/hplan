# Domain Context — Agent Interop & Portability

## 무엇을 연결하나 (먼저 규정)

- 도구·컨텍스트 연결 → MCP 계열
- 에이전트 ↔ 에이전트 위임 → A2A 계열
- 멀티 하네스 동일 스킬셋 → 표준보다 이식성·파일 상태 우선

## 연결 표준 비교 축

| 축 | 질문 |
|----|------|
| 범위 | 도구인가 에이전트인가 |
| 성숙도 | 스펙 안정·구현체 수 |
| 생태계 | 채택 벤더·툴 수 |
| 이탈비용 | 다른 표준으로 옮길 때 비용 |
| 철회 가능성 | 베팅을 되돌릴 수 있나 (옵션 가치) |

신생 벤더 표준(예: 구글·MS 공동 발표 연결 표준)은 *옵션*으로 관찰하되, 상태를 묶지 않는다.

## 이식성 매트릭스 (자산별)

| 자산 | 이식성 | 처리 |
|------|--------|------|
| SKILL.md 본문 | 높음 | 한 벌 유지, 복사 |
| context/examples/references | 높음 | 본문과 함께 이동 |
| commands (슬래시) | 낮음 | 하네스별 얇은 어댑터 |
| hooks | 낮음 | 어댑터 + fallback 스크립트 |
| 전송/도구 바인딩 | 어댑터 | 본체에서 분리 |

## 파일 = durable state 패턴

- 상태(메모리·로그·결정·인덱스)를 markdown+frontmatter 파일에 둔다
- 전송은 교체 가능한 어댑터, 상태는 파일에 보존 → 표준 변화에 면역
- frontmatter를 상호운용 포맷(공개 지식 포맷)에 맞추면 타 도구도 읽음
- "File over app": 앱·전송이 아니라 파일이 1급 자산

## lock-in 점수

- Low: 전송 교체해도 본체·상태 보존 (어댑터 격리 + 파일 상태)
- Med: 본체는 보존되나 전송 교체에 어댑터 재작성 필요
- High: 상태까지 단일 벤더 전송/저장소에 묶임 → 표준 변화 = 전면 마이그레이션

## 경계
- 연결 표준은 권한·DLP·정지를 보장하지 않는다 → operate:govern 으로 분리
- 내부 협력 패턴은 orchestration, 메모리 계층은 memory-arch

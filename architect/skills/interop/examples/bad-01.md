# Bad — 신생 표준에 상태까지 올인

```
"방금 발표된 연결 표준이 대세 될 것 같으니, 전 에이전트를 거기에 맞춰 재작성하고
 메모리·로그도 그 표준 저장소에 넣자. 어댑터 같은 건 오버엔지니어링이야."
```

❌ 문제점
- 미성숙 표준에 전송 + 상태를 동시에 묶음 → 표준이 바뀌면 전면 마이그레이션
- 철회 가능성(옵션 가치) 미점검 — 되돌릴 길을 닫음
- 이식 가능/비이식 자산 미분리 → Codex·Cursor로 못 옮김
- 상태를 전송 저장소에 둠 (파일=durable state 원칙 위반)
- lock-in High인데 그걸 인지조차 못 함

→ 재작업
1. 지금 필요한 게 도구 연결인지/위임인지/멀티 하네스인지 규정
2. 새 표준은 어댑터 뒤로 격리 (옵션으로만 채택)
3. 상태는 markdown+frontmatter 파일로 분리
4. lock-in 점수 산정 + 재검토 트리거 명시

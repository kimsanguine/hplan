# Test Cases — govern

## 트리거되어야 함 (Use)
- "이 에이전트가 데이터를 지울 수 있는데, 누가 승인하나?"
- "런칭 전에 감사 추적(audit trail)이 필요하다"
- "프로젝트 끝났는데 에이전트가 아직도 돌고 있다 — 정리해야 한다"
- "에이전트를 멈출 수 있는 사람이 누구인지, 롤백은 되는지 점검해줘"
- "고객 결제 에이전트 배포해도 통제 가능한지 보안 게이트 돌려줘"
- "에이전트 도구 권한이 과한지 최소권한으로 감사해줘"

## 라우팅되어야 함 (Route, govern 아님)
- "응답 3%가 환각인데 허용 가능한가?" → reliability (신뢰성/SLA)
- "에이전트가 30분간 응답이 없었다, 원인 분석" → incident (사후 대응)
- "토큰 비용이 40% 뛰었다" → ops-review (비용/번레이트)
- "시스템 프롬프트에 도구를 어떻게 정의하지?" → deliver:instruction

## 경계 (Boundary)
- 도구·데이터 인벤토리 없음 → 점검 불가, 먼저 인벤토리 확보 요구
- "이 게이트 = 법적 컴플라이언스 완료?" → 아니오, 체크리스트일 뿐 (법무 위임)
- 내부 읽기전용 저위험 에이전트 → dlp·audit만, 풀 게이트 강제 금지

## 품질 assertion
- 출력에 위험 등급(민감도×권한)이 산정되어 있다
- "누가 멈출 수 있나" 매트릭스가 실행 가능한 형태로 채워진다
- 최종 판정이 GO/CONDITIONAL/NO-GO 중 하나로 수렴한다
- 미충족 시 선결 조건이 명시된다
